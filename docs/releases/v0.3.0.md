Linux CRU 0.3.0

COSMIC support, a reworked interface, and KDE Plasma 6.8.

**COSMIC**

The outputs, their modes, the active one and the adaptive-sync state
are read through `cosmic-randr`, and the mode is selected with it.
COSMIC cannot create a mode of its own (pop-os/cosmic-epoch#2577), so
the mode is added to the display's EDID -- and because COSMIC reads the
display's modes when it starts, that happens at boot, through the
systemd service.

**A new interface**

Light and dark palettes that follow the desktop's own theme, the modes
the display actually offers in a list you can click, resolution
presets, a preview of every command that will run, and a log of
everything that was done. The settings are remembered between runs.

**KDE Plasma 6.8**

`kscreenctl` takes a full modeline, so the timings reach the display
exactly as calculated instead of the compositor re-deriving them --
CVT-RBv2, GTF and modelines pasted from Windows CRU all work.

**Other fixes**

- The X11 configuration can be removed again, like the EDID overrides.
- The tool asks the driver which resolutions it has before choosing
  between the compositor and the EDID override, and takes away the
  custom modes that depended on an override it just removed.
- The preview shows the file that is really written, and the VRR
  caveat that applies to EDID overrides on the NVIDIA driver.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
