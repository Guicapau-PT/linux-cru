Linux CRU 0.4.0

Plasma display settings, and a window that keeps drawing.

**Plasma display settings (KDE Plasma 6.8)**

HDR, wide colour gamut, the colour depth, the scale and the rotation
of the selected display are read from the desktop, shown as it
reports them, and set on it — and a control the display cannot use is
switched off instead of failing when clicked. Adaptive sync shows the
policy in force, and switches itself off for a display that does not
report it.

**A window that keeps drawing**

Every kscreenctl call is a process and a round trip to KWin over
DBus, and a window that waits for one stops drawing — a stutter the
desktop, not the tool, feels. The interface asks off its own thread
now and keeps the answers for a moment, so the mode list and the
settings fill in while the window stays alive.

**The mode list, the way the display settings show it**

The mode list comes out sorted, largest first and faster rates
first, with the doubled timings taken out and the custom modes
marked. A mode the display already runs is left alone: asking for it
again says so instead of taking the picture apart for nothing.

**Other fixes**

- On Plasma 6.8.1 a just-added custom mode has an id in the JSON
  answer, so switching to it does not need a second question; older
  releases fall back to the mode list.
- The display settings are detected as they are, and what the
  desktop cannot do with the display is written down rather than
  guessed.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
