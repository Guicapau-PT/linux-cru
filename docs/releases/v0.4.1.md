Linux CRU 0.4.1

The preview says what the kscreenctl calls really do.

`add-custom-mode` adds a mode; it does not switch to it — a
`set-mode` does, addressed by the id the JSON answer reports for the
mode that was added. The preview of a Plasma 6.8 apply claimed the
add did both, so anyone running the commands by hand would not have
reached their mode; the corrected preview, and the README, tell the
two apart. (The tool itself always ran them as the two steps, and
keeps the removal of the added mode when the switch is refused.)

Also in this release:

- "Making a release" now records that the publish step reads the
  release notes from the repository, which is what made the 0.4.0
  workflow fail after its AppImage had already been built.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
