Linux CRU 0.4.2

The command line can now undo the tool on a machine whose desktop
cannot start. A kernel update can turn a display setup that worked
into a login screen that freezes, and until now the only undo the
tool had was its Remove button — which needs the interface, which
needs Tk, which a recovery TTY does not offer. `--remove-overrides`
does what the Remove button does, from a terminal or over SSH: the
EDID overrides (either method), the X11 configuration and the stretch
setting go in one go, root is asked for the usual way — a terminal
password prompt when no authentication agent is around — and a run
without a confirmation or `--yes` refuses to act rather than guessing.

Also in this release:

- Every command-line flag runs before tkinter is imported now. An
  interface that could not start used to take `--detect` down with
  it, which is the wrong thing for the flag that exists to diagnose
  the machine; only the window needs Tk.
- `--detect` reports what this tool has installed (`state:`), so on a
  boot that went wrong a TTY already answers the "was it me?" question
  before anything needs to be fixed.
- The environment's bootloader answer is the installer's answer now:
  it comes from persist.py, knows limine and the UKI command line,
  and the older detection that missed limine is gone.
- The tests for all of it: test_cli runs the launcher with a tkinter
  that refuses to import and proves the flags still work; test_rescue
  exercises the undo end to end in a sandbox, the same way the
  persistence tests do.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
