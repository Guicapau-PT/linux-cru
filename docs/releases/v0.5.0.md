Linux CRU 0.5.0

GNOME 48 and newer are no longer read-only. The tool still cannot
create a mode on GNOME -- Mutter has no such feature, and the kernel
EDID override remains the way a custom resolution gets in -- but once
the mode is there, the tool can do what GNOME's own Settings do, and
more of it, without leaving the window:

- The modes Mutter has are read through gdctl, so the mode list and
  the active mode reflect the desktop rather than the kernel's.
- The selected mode can be switched to straight away, including a mode
  that an EDID override just added (once GNOME has read it), with the
  rest of the layout -- the other displays, their scales and
  rotations -- left alone.
- The scale and the rotation of the selected display can be set from
  the interface, and the available scales are the ones the mode
  actually supports.
- The refresh rate can be changed from the Display settings card. That
  is the setting that makes a desktop feel smooth, and GNOME hides it
  behind Settings > Displays, so it is worth having where the mode is.
- Adaptive sync (VRR) is a mode variant on GNOME, so the tool switches
  to the `+vrr` variant of the same timing instead of pretending it
  has a separate policy. The card says so when the display offers no
  variable variant.

Also in this release:

- The GNOME path no longer refuses to switch when more than one display
  is connected: the whole layout is rebuilt from what gdctl reports and
  only the chosen output is changed.
- The test suite gained a GNOME backend suite against a frozen
  `gdctl show --verbose` sample, so the parser and the layout
  reconstruction can be checked without GNOME running.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
