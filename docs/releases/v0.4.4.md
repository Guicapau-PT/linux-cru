Linux CRU 0.4.4

The Guide button tells the truth now — and the browser gets a clean
environment to run in.

Opening the guide (or a release page, when the version announces an
update) claimed "The guide is open" without checking whether anything
was started. On a fresh install with no default browser set, or when
the AppImage handed its own library path to the launcher, nothing
would open and the tool would boast anyway. Both are fixed: the
opening goes through the same environment handling the other system
tools get, both the desktop launcher's answer and the fallback's are
checked, and when nothing opens the status line carries the URL
instead of a boast, with a note on where default browsers are set.

Also in this release:

- The URL is written to the log either way, so it can be copied from
  there whatever happened.
- The guide's troubleshooting mentions what to do when no browser is
  set up: KDE's System Settings → Applications → Default Applications,
  `xdg-settings set default-web-browser`, or `$BROWSER`.
- Tests cover the opening logic without browsers being launched: what
  happens when the desktop answers success, when it answers failure,
  when no fallback exists, and when the fallback crashes.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```
