Linux CRU 0.4.3

There is a guide now, the version is visible in the window, and the
tool quietly asks once in a while whether a newer release exists.

The guide (the Guide button in the window, or docs/guide.md) is
written for someone who has never built a modeline: the three layers
— display, driver, desktop — and what each of them decides, the
window part by part, the timing standards in one table, and the tasks
people actually come for in walkthrough form. Two of them are the
classic ones: *2560x1440 with black bars* on a wider panel, and
*stretched to fill* for the shooter setup — including who scales
what, which monitor setting does it instead, and where every piece of
the stretch lives on disk. When a mode fails to show up, the
troubleshooting steps and the Remove/recovery commands are in there
too, so a problem never needs a forum thread to solve.

Also in this release:

- The version sits at the bottom right of the window. When a newer
  release is published, the announcement goes there: "v0.4.3 →
  v0.4.4 available".
- The check runs at most twice a day, from the window's own thread,
  against this fork's releases; a machine that is offline stays
  quiet. Clicking the version asks again right away and opens the
  release page when there is news. `--check-updates` asks the same
  question from the command line — one of the flags that work without
  tkinter.
- The update logic is tested without touching the network (the fetch
  is a stub): what counts as newer, an offline machine, and the
  command's answers; the interface's tests switch the automatic check
  off, so building a window never asks the network anything.

The AppImage bundles Python, tkinter and the whole Tcl/Tk runtime, so
it does not need anything installed on your system.

```
chmod +x Linux_CRU-x86_64.AppImage
./Linux_CRU-x86_64.AppImage
```

This is a fork of [PhialsBasement/linux-cru](https://github.com/PhialsBasement/linux-cru);
the research, the timing calculators and the EDID engine are theirs.
